## 1. 背景与问题

### 1.1 现状

当前游戏界面是「网页卡片式」DOM 渲染：

- **大厅**：预约清单列表页——顶部标题 + 患者卡片列表 + 右侧操作侧栏，无空间感，患者是一张张卡片而非「在诊所里的人」。
- **对话治疗**：聊天流 UI——左侧患者立绘 + 状态条，右侧聊天气泡滚动历史，底部选项按钮。
- **HUD**：顶栏文本状态条（等级/金钱/声望/理智/日期）。
- **设施**：`clinicUpgrades` 是 6 个字符串升级项，只改变数值与文字，无场景体现。
- **角色**：纯 CSS 手绘 Chibi 小人（`ChibiCharacter`）仅用于对话静态立绘；大厅场景 v1.3 起不绘制小人，患者以候诊名牌呈现。
- **资产**：`public/images/clinic-bg.jpg`、`title-bg.jpg` 两张 AI 生成治愈插画背景 + 1 首 BGM。美术方向重构中：补齐全套场景背景（大厅/诊室/功能面板），见 §4 决策 7。

### 1.2 痛点

1. 诊所没有「空间」——经营感弱，患者与设施不存在于同一个可视空间里。
2. 对话治疗是「聊天软件」式，而非「面对面咨询」——叙事沉浸感打折。
3. 界面形态（卡片/聊天流/侧栏列表）与开罗式模拟经营的「场景驱动」范式差异大。

### 1.3 目标

将界面重构为**治愈系手绘模拟经营**风格——参考《Cozy Grove》《Spiritfarer》《动物森友会》式温暖手绘的质感与叙事沉浸，不模仿开罗的像素经营数值面板。核心转变：

- **全量场景化**：经营层（大厅俯视场景）与叙事层（诊室面对面对话）都进入可视空间。
- **场景化交互**：点选导航、点击对象弹菜单、底部菜单栏、顶栏常驻数值。
- **治愈手绘风**：界面整体为「温暖纸木质」——纸感卡片、手绘细描边、木纹边框、低饱和暖色，背景插画始终透出。

## 2. 目标与非目标

### 2.1 目标

| 目标 | 描述 |
| --- | --- |
| 俯视大厅场景 | 诊所大厅 2D 俯视：设施可视化 + 候诊名牌卡片（患者不画小人），背景插画铺底 |
| 候诊名牌开诊 | 患者以暖色名牌呈现于候诊区，点击名牌直接开诊（无医生小人导航，v1.3 决策） |
| 诊室面对面对话 | 治疗在诊室场景发生，医生与患者相对而坐，逐句气泡，右上角可回顾 |
| 设施装修模式 | 进入装修模式可拖动设施重排位置（位置仅视觉，不影响数值） |
| 悬浮 HUD 与底部菜单 | 顶栏常驻核心数值，底部菜单栏承载全部功能入口（精简换肤，图标手绘化） |
| 全量界面统一 | 信件/成就/技能树/发现客户/结局等全屏面板统一纸木质风格，移除旧 DOM 大厅/对话 |
| AI 治愈插画背景 + 交互叠加 | 场景背景用 AI 生成治愈系插画（全屏铺底，用户渠道生成）；设施/候诊名牌等交互元素程序绘制叠加在背景上（不绘制小人） |
| 纸木质界面质感 | 面板/卡片统一「温暖纸木质」：纸感底色 + 手绘细描边 + 木纹边框 + 低饱和暖色；图标与字号偏大、清晰、高对比，背景插画始终透出 |

### 2.2 非目标（本版本明确不做）

| 非目标 | 说明 |
| --- | --- |
| 像素画风 | 保持温暖手绘风，非 16bit 像素 |
| 摆放影响数值 | 设施位置仅视觉，不影响动线/效率/覆盖等数值 |
| 家访场景 | 回访仍在现有界面发生，患者家中场景后置 |
| 开罗式经营评定 | 年结清算/最高分/二周目继承，后置 |
| 多周目 | 不做 |
| 原生 App / 移动端新形态 | 桌面 Web 为主，响应式基本保障（见 SPEC） |

## 3. 用户体验目标

### 3.1 玩家旅程

1. 进入大厅 → 看到诊所俯视全貌：插画背景 + 设施分布 + 候诊区患者名牌卡片（不画小人）。
2. 点击患者名牌 → 场景切到诊室，两人相对而坐。
3. 治疗中 → 说话者头顶冒气泡逐句推进，底部选项可点，右上角小窗可翻对话回顾，患者四维状态条常驻。
4. 治疗结束 → 回大厅，患者记录更新。
5. 点击设施 → 弹操作面板（查看/升级/装修）。
6. 点「装修」→ 进入装修模式拖动设施到网格位置。
7. 底部菜单栏 → 一键打开技能树/消息/追踪/成就/发现客户等面板。
8. 顶栏 → 等级/金钱/声望/理智/日期永远可见，数字随经营跳动。

### 3.2 设计基调

- **温暖治愈**：暖色主调、纸木质质感、柔和圆角、无压迫感——界面如手账/木牌般亲切。
- **叙事沉浸**：背景插画是画面的绝对主角，界面元素半透纸感叠在其上，绝不全屏盖住场景。
- **清晰可读**：图标与字号**偏大**、字形清晰、前景文字与背景对比度高；对话框/选项/记忆碎片可读性不降级。
- **场景即信息**：患者等待天数、情绪、状态尽量在场景里可读（名牌上的姓名/情绪点），减少跳转。

## 4. 设计决策记录（grill-me 共识）

> 以下 9 项经逐题共识锁定，SPEC/PLAN 必须遵循。

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 重构范围 | **全量场景化**（经营层 + 叙事层都进场景） | 用户明确要求，对话做进场景面对面 |
| 2 | 视觉风格 | **治愈系手绘插画背景 + 程序绘制交互元素 + 纸木质界面**（非像素、非开罗） | 背景采用 AI 治愈插画（对标现有 clinic-bg.jpg 画风，水彩/厚涂），交互元素保持暖色手绘语言；界面统一「温暖纸木质」质感 |
| 3 | 技术分工 | **Phaser 场景 + React UI 覆盖层**，EventEmitter 桥接 | 符合 Phaser+React 最佳实践，现有组件复用 |
| 4 | 场景结构 | **大厅 + 诊室**双场景 | 大厅承载经营，诊室承载对话，家访后置 |
| 5 | 医生控制 | **不绘制医生小人，点名牌直接开诊**（v1.3） | 原「可见 + 点选导航」随移除小人决策取消：插画背景保持纯净，免去导航等待 |
| 6 | 设施摆放 | **装修模式半自由**（位置仅视觉） | 保留摆放乐趣，避免平衡复杂度 |
| 7 | 资产方案 | **AI 生成插画背景 + 程序绘制交互叠加** | 背景图由用户用 AI 绘图工具按风格 prompt 生成（MiMo 无文生图，走用户渠道）；交互元素（设施/候诊名牌）程序绘制叠加在背景上，可迭代替换；**小人不再绘制**（v1.3） |
| 8 | 分期 | **五期 M1-M5**，每期独立可玩可提交 | 风险隔离，工程量大需拆细 |
| 9 | 对话形态 | **面对面逐句气泡 + 右上角对话回顾小窗** | 沉浸式咨询感，历史可查 |
| 10 | 界面质感 | **温暖纸木质 + 图标/字号偏大、高对比**（非开罗像素面板） | 用户决策：游戏是治愈系心理叙事模拟，与开罗经营数值游戏是两类；界面如手账/木牌，清晰易读 |

## 7. 成功指标与验收

1. **每期独立可玩、独立提交**——M1–M5 各阶段结束游戏可运行、可验证、可回滚。
2. **存档兼容**——v1.0.0 新版本可读取旧存档（`ps.save.v1`），数据层零改动。
3. **现有测试保持通过**——vitest 全部用例（含 GameState / sceneBuilder）不因重构失败。
4. **数据层零改动**——`lib/data`、`lib/engine`、`lib/state` 重构期间不因界面需求修改（除必要时纯新增）。
5. **文本可读性不降级**——对话/选项/记忆碎片在场景化后依然清晰（SPEC 硬约束）。
6. **玩法等价**——重构后所有既有功能（获客/升级/回访/结局/成就）行为一致，仅呈现方式变化。

## 8. 风险与缓解

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| ~~CSS Chibi → Phaser Graphics 程序绘制表达力不足~~ | ~~中~~ | **风险消除**（v1.3 不绘制场景小人）；对话静态立绘保留 DOM Chibi |
| React overlay 与 canvas 的 z-index/遮挡问题 | 中 | 分层规范：canvas 基底 + overlay 绝对定位 + portal 弹窗顶层（沿用现有 createPortal 经验） |
| 每帧全量同步 store 导致性能问题 | 中 | Phaser 只读 store、事件驱动同步；禁用每帧轮询，变更通过事件/回调推送 |
| 点选导航寻路（障碍/碰撞） | 中 | 网格化简化寻路（A* 或网格步进），场景障碍物少量且固定 |
| AI 生成背景与程序绘制交互元素的透视/风格协调 | 中 | prompt 规定构图（地面区/门/前台位置），生成后 vision 标定坐标；交互元素简约、按深度排序弱化透视差 |
| 响应式/移动端 canvas 缩放 | 低 | Phaser Scale 模式 + 覆盖层 rem 布局，小屏菜单重排 |
| 工作量巨大、长周期 | 高 | 五期拆解 + 每期独立提交回滚 + 每期验收 |
