# 患者剧本编写提示词（可复用智能体模板）

> 用途：教会任何智能体持续编写与林晓同标准的患者剧本。
> 标准样板：`docs/stories/lin-xiao-v3.md`（已定稿的长剧本样板，读它 = 理解全部写作质感要求）。
> 本提示词是「工作手册」：给出方法论、硬性规则、落地步骤与验收清单。写作过程中如与样板冲突，以样板为准。
> 剧本分**短 / 中 / 长**三档，按需要的会谈体量选档，方法论相同、参数不同（见第二步）。
>
> **使用方式（派活）**：派活给 agent 时，把「第 0 步 · 新剧本创作流程」到「第 0 步的禁止事项」的整段（含本节）复制给目标 agent，填入两个占位：`<主题>`（一句话，如「急诊科护士，长期面对生离死别后开始逃避值班」）、`<档位>`（短 / 中 / 长，可留空让 agent 按主题复杂度自定）。本文件是唯一权威剧本写作规范（已并入原「派活提示词-新剧本.md」）。

## 第 0 步 · 新剧本创作流程（从主题出发）

> 本节是「给定一个主题，从零创作完整剧本」的派活流程。创作完成后按「第六步 · 落地步骤」转换、「第七步 · 验收清单」验收。

**输入**：主题 `<主题>`，档位 `<档位>`（短 / 中 / 长）
**输出**：`docs/stories/<患者id>-v3.md` + `lib/data/patients/<患者id>.ts` + `lib/data/<患者id>.walk.test.ts`（聚合入口由 `scripts/scan-patients.mjs` 扫描目录自动生成索引，新剧本入目录即进池，无需手动接聚合入口）

### 第 0.1 步 · 查重（动笔前必做）

读 `docs/stories/剧本登记表.md`，确认你的核心困境 / 主题 / 身份设定不与表中任一已有剧本雷同（同一困境换皮 = 违规）。登记表末尾的「防雷同提示」列了已被占位的坑位，新剧本避开。不雷同再往下写。

### 第 0.2 步 · 人物设计（五要素，仿 lin-xiao-v3 / chen-mo-v3 的档案写法）

- **姓名 / 年龄 / 职业 / 来诊渠道**（谁送来的、为什么是现在）
- **一句话核心**：这个人的困境用一个比喻说透
- **三层真相**：表层（开场就说，症状）+ 中间层（第 2-3 节拍揭，具体事件）+ 深层（核心信念，根源，儿童期成因）
- **角色三角**：施压者（谁在施加压力）/ 情感忽视者（谁没接住）/ 被守护者（他在保护谁）——至少两角具象
- **症状意义**：症状不是病，是他在某个处境下的「求生方式」，开场埋、中段被问、高潮意义反转
- **关键转折**：整场最重要的一个瞬间（一句话或一个动作），是情感顶点

人物设计符合游戏定位：**弱化治疗术语，强调人与人的连接**。不出现 CBT / 催眠 / 药理等术语。

### 第 0.3 步 · 定档位 + 节拍规划

档位决定规模（派活已指定就用指定档）：短 4 节拍 / 中 5 节拍 / 长 6 节拍，参数见第二步三档表。每节拍规划：主题一句话、trust 起止、truth 起止、1 个阻抗节点、1 个关键事件、碎片落点、过场（narration）归位。把节拍规划表写在剧本开头（给审稿人看，也给自己定数值）。

### 第 0 步的禁止事项

- 核心困境/主题与登记表已有剧本雷同（同一困境换皮）即违规；产出前必须查重。
- 不修改 `lib/engine/`、`lib/types.ts`、`scripts/md-to-patient.mjs`、`lib/data/patients.ts` 以外的已存在文件；`patients.ts` 是扫描生成的聚合入口，**也不需要改**。
- 患者 id 不与现有冲突（先 `ls lib/data/patients/` 确认）；中文名转拼音 snake_case，全局唯一（现有：`lin_xiao` / `chen_mo` / `xiao_bei` …）。
- 剧本里不出现治疗术语（CBT / 催眠 / 药理等）与患者口述时间词。

## 第一步 · 必读（动手前先读完，不许跳过）

按顺序读这四份，读完后你才能动手：

1. `docs/stories/lin-xiao-v3.md` — **长剧本标准样板全文**。你要复刻的成品：结构、密度、文案质感、数值标注方式就是你的模板。短/中剧本是它的缩小版——节拍数变少、轮数变少、trust 终点变低，但文案质感和每节拍内部的写法不变。全文约 1100 行，读完。
2. `lib/types.ts` — 数据结构定义。`PatientScenario` / `DialogueNode` / `DialogueChoice` / `ChoiceEffect` / `MemoryFragment` / `EndingType` 这些字段的含义、可选性、约束都在这里，写出来的结构必须一一对得上。
3. `lib/engine/DialogueEngine.ts` — 运行时机制。重点看：
   - `choose()`：`round` 每走一个 choice 节点 +1；`enterNode` 时查记忆碎片；碎片按 truth/trust 达到阈值触发一次
   - `minRounds`：简单 5 / 普通 6 / 困难 8，round 不足会自动插 pad 节点兜底——**所以主线设计 40/70/100 轮就是为了永不触发 pad**
   - `continue()`：无选择节点（patient / narration）走 autoNext 自动推进，**不占轮次**
   - `meetsRequirement`：require 门槛不满足时选项显示但点不动（浮窗提示）
4. `lib/data/patients.ts`（聚合入口）+ `lib/data/patients/lin_xiao.ts`（完整长档样例，含全部节拍边界 `beatEnd` 标记）+ `scripts/md-to-patient.mjs`（v3 剧本转换器）— 看清落地形态与转换产物（见第六步）。
5. `docs/stories/剧本登记表.md` — 全部剧本的内容概述索引，**创作前必读，防雷同**（见第 0.1 步）。
6. `lib/engine/walk.ts` — 走线器 + PICKS 四策略（`--walk` 测试的走线判定逻辑）。

## 第二步 · 会谈节拍制方法论（剧本的核心结构）

### 为什么用节拍制

- 引擎零改动：`round` 只增不减，主线轮数足够则不触发 pad；断点/回顾/碎片机制原样可用。
- 单次会谈过长玩家腻，且四维数值必然打满。节拍制让数值在**节拍间经「过场」（narration）叙事性时间跳跃**，曲线可设计；每节拍一个主题、一次「见面」，情感有起落。
- 天然满足故事深度标准「结局有过程」——玩家真的陪患者走了几周。

### 三档体量选型

| 档位 | 主线选择数 | 节拍数 | 每节拍轮数 | 用途 |
|---|---|---|---|---|
| **短** | **40 次以上** | 4 | 10–12 轮 | 单症状患者、支线、快节奏体验 |
| **中** | **70 次以上** | 5 | 14–16 轮 | 常规患者，标准体量 |
| **长** | **100 次以上** | 6 | 16–18 轮 | 核心患者、完整治疗历程（林晓 = 此档） |

### 各档硬性参数（抄样板，不许改）

| 项 | 短（4 节拍） | 中（5 节拍） | 长（6 节拍） |
|---|---|---|---|
| trust 锚点 | 15→28→40→50→58 | 15→30→45→57→65→70 | 15→30→50→65→75→80→88 |
| 每节拍增量 | +13/+12/+10/+8 | +15/+15/+12/+8/+5 | +15/+20/+15/+10/+5/+8 |
| truth 终点 | 0→40 | 0→70 | 0→100 |
| 碎片阈值 | 30 | 25 / 50 | 30 / 40 / 80 |
| 恶化入口 | trust ≤ 40 | trust ≤ 55 | trust ≤ 70 |
| 隐藏结局门槛 | trust 50 | trust 65 | trust 80 |
| 结局路径轮数 | 节拍4，cure 主线 ~6 轮 | 节拍5，cure 主线 ~10 轮 | 节拍6，cure 主线 ~14 轮 |

### 各档节拍主题推进模板

```text
【短 · 4 节拍 · 40+ 轮】
节拍1  初访·表层     trust 15→28  truth 0→10  阻抗 1
节拍2  中间层触发    trust 28→40  truth 10→20  [m1 碎片]  require 20 起
节拍3  深层信念      trust 40→50  truth 20→30  恶化入口 @trust≤40
节拍4  转向+结局     trust 50→58  truth 30→40  require 30 / 隐藏@50

【中 · 5 节拍 · 70+ 轮】
节拍1  初访·表层     trust 15→30  truth 0→15  阻抗 1
节拍2  外部触发·中间层 trust 30→45 truth 15→25  [m1 碎片]  require 25 起
节拍3  第一次复访·深层 trust 45→57 truth 25→40 [m2 碎片]  require 40
节拍4  根源信念      trust 57→65  truth 40→55  恶化入口 @trust≤55
节拍5  转向+结局     trust 65→70  truth 55→70  require 45 / 隐藏@65

【长 · 6 节拍 · 100+ 轮】
节拍1  初访·表层     trust 15→30  truth 0→15  阻抗 1
节拍2  外部触发·中间层 trust 30→50 truth 15→30 [m1 碎片]  require 30 起
节拍3  第一次复访·深层 trust 50→65 truth 30→50 [m2 碎片]  require 45
节拍4  根源信念·七岁根 trust 65→75 truth 50→65 require 50
节拍5  第二次复访·高潮 trust 75→80 truth 65→90 [m3 碎片] 恶化入口 @trust≤70
节拍6  安全网·转向+结局 trust 80→88 truth 90→* 路径选择 + 结局路径
```

**每个患者替换的是「人物档案」「症状」「真相」「阻力来源」，节拍骨架和数值曲线形状原样套用。**

### 通用结构规则（各档一致）

- 时间跳跃：用 narration 过场节点（不计轮），文本里用自然叙述（如「一周后她复访」）。
- **节拍间 = 治疗分期复诊（断拍，SPEC v1.6.0）**：节拍与节拍之间隔一段时间——每个节拍结束处是一个 `narration`「患者离开」节点，语义上患者离开诊所；玩家点击「继 续 ▸」后患者离场，**1~3 天后复诊到访**再开启下一节拍（复诊消耗当日名额）。见下方「断拍标记」约定。
- 实质选择 : 轻推进 = **约 1:2**（1/3 实质 +2~+3 带 require；2/3 轻推进 +1~+2 或纯叙事）。
- 每节拍固定元素：1 个**阻抗节点**（防御短时回升）+ 1 个**关键事件**（推动真相）。

### 断拍标记（beatEnd · 机器可解析，转换器自动校验）

每个节拍的结束节点（narration「患者离开」）加 `beatEnd: { resumeNode: "<下一节拍起始节点>" }`：

```ts
{
  id: "l1_out",
  speaker: "narration",
  text: "她起身，把书包拿起来，又摆了一次才背好。走到门口，她回头看了你一眼……",
  beatEnd: { resumeNode: "l2_start" },
  autoNext: "l2_start",   // 兜底：引擎优先 beatEnd，其次 autoNext
}
```

硬性规则：

1. **边界数 = 档位节拍数 − 1**：短 3 处 / 中 4 处 / 长 5 处。末节拍结束是 `isEnding` 结局节点，**不加 beatEnd**。
2. `resumeNode` 指向下一节拍起始节点（`X2_start` / `X3_start` …），必须存在。
3. 边界节点是 narration（无 choices），天然复用「继 续 ▸」按钮交互。
4. 无节拍的剧本（引导患者小北）不标记。
5. `autoNext` 保留作兜底（引擎优先判 beatEnd）。

### 文案密度参考（抄样板的节奏）

- 每节拍开头：`narration` 过场（场景描写，autoNext→患者首句）
- 患者节点：一段口述（1–3 行），带 `emotion`，autoNext→医生节点
- 医生节点：2–4 个 choice，每条含 `kind` + `effect` + `next`；带 require 的写明门槛
- 阻抗节点设计成「关键分叉」：选项之一引向阻抗反弹分支，反弹后再汇回主线
- 文本里给关键情绪锚点留物件/动作细节（如林晓的掐手背、摆三次书包、那幅被撕的画）

## 第三步 · 数值曲线规则（信任合并线，不可违背）

### 四个维度怎么涨

| 维度 | 规则 |
|---|---|
| **trust** | 单调递增，起点 15，终点按档位（58/70/88）。**empathy 与 probe 同涨 trust**（信任 = 真诚互动的度量，不分线）。轻推进 +1、实质 +2、纯过场 +0。**失误项（logic/prescribe 说教）显著负值 −5~−15** |
| **truth** | 单调递增。**只由 probe 涨**：轻 +2、实质 +3（探问越深、真相揭示越多） |
| **defense** | 净下降（长档 70→22）。阻抗节点短时 +8~+12 再回落 |
| **mood** | 全程波动（冲突 −8 / 和解 +10），节拍过场回中 |

### trust 锚点曲线（逐节拍必须精确达标）

设计每节拍 choice 时，先按对应档位的增量配 effect 总和，再补轻推进节点填满该节拍轮数（短 10–12 / 中 14–16 / 长 16–18）。

### 记忆碎片阈值（按档位）

- 长：30 / 40 / 80（均衡 50/50 玩家触发 m1+m2，探问专精触发全部三枚）
- 中：25 / 50（均衡玩家触发两枚）
- 短：30（单碎片）
- 每碎片一段第一人称闪回记忆画面（患者视角），只触发一次

### require 门槛递进（按档位）

| 用途 | 短 | 中 | 长 |
|---|---|---|---|
| 锋利切入 | trust 20 | trust 25 | trust 30 |
| 深层逼问 | trust 30 | trust 40 | trust 45 |
| 根源揭示 | trust 35 | trust 45 | trust 50 |
| 恶化入口 | trust ≤ 40 | trust ≤ 55 | trust ≤ 70 |
| 隐藏结局 | trust 50 | trust 65 | trust 80 |

### 失误项设计（恶化入口的扳机）

- 每节拍埋 1–2 个「说教式」错误选项（logic/prescribe），**显著负 trust（−5~−15）**，防御上升。
- 系统性失误（选 2–3 个失误点）的玩家，最后节拍前 trust 掉到该档恶化门槛以下 → 恶化入口才可见。
- 失误分支患者会有阻抗反弹文案（如「你也这么说？」），再汇回主线。

## 第四步 · 结局设计（各档都是 4 条）

| 结局 | 形态 | 奖励示例 |
|---|---|---|
| **cure** | 患者真正走出困境，复访给证据 | rep +8 / money +300 / exp +50 / sanity +5 |
| **acceptance** | 未完全治愈但与症状和解 | +4 / +180 / +35 / +6 |
| **hidden** | 特殊伦理结局（如强制介入） | −10 / +100 / +80 / −15 |
| **worsen** | 情况变糟（**唯一入口 = 说教选项，trust≤该档门槛才可见**） | −8 / +50 / +10 / −20 |

- 每条结局都必须有**过程与证据**（不是跳切），文案在正文里已铺垫。
- **「依赖」结局已砍**，不要写。
- 最后节拍的路径选择：安全网（cure 主线）/ 接纳 / 隐藏（require 门槛见上表）。
- 结局节点要有 `endingType` / `endingTitle` / `endingText` / `endingReward`。

## 第五步 · 文案硬性规则（违反即返工）

1. **患者口述中禁止叙事性时间词**：「第二天」「一个月后」「后来有一天」全部不行。要用正常口语——「这周」「上次」「那会儿」。时间跳跃只准写在 narration 过场里。
2. 患者口述用第一人称、口语化、有停顿感（省略号表现压抑），1–3 行。
3. 每句患者台词配 `emotion`（八个枚举之一，跟着情绪走）。
4. 医生选项文本是「说给患者听的话」，不是描述；描述性内容放 narration。
5. 阻抗要「真」：患者会反驳、会冷下来、会反弹，但会汇回主线。
6. 结局信（引擎 `generateLetter` 会生成）不写，引擎兜底。

## 第六步 · 落地步骤（v3 格式 → 转换器 → 聚合入口）

1. 按「输出格式规范」写 v3 剧本文档（含 `ts-meta` 验证参数注释 + 全部 `ts-dialog` 节点块）。**不要手写 TS 剧本文件**——剧本的权威来源是 v3 markdown，改剧本只改 md 再跑转换器。
2. 跑转换器（自动结构校验 → 生成患者 TS → 类型检查）：

   ```bash
   node scripts/md-to-patient.mjs docs/stories/{姓名}-v3.md --walk
   ```

   - 生成 `lib/data/patients/{id}.ts`（导出具名 `patient`）
   - `--walk` 额外生成 `lib/data/{id}.walk.test.ts`（四线走线验收测试，断言从 ts-meta 注释读取）
   - 结构校验不过会带行号报错，回到文档修正再跑

3. 在聚合入口 `lib/data/patients.ts` 补 import + 加入 `allPatients`：

   ```ts
   import { patient as patient新变量 } from "./patients/{id}";
   export const allPatients: PatientScenario[] = [patientG, patientC, patientA, patientB, patient新变量];
   ```

4. 跑 `npm test`，全绿即完成。
5. 走线模拟验证（见下）已由 `--walk` 生成的测试覆盖。

## 输出格式规范（v3 · 机器可解析）

交付一份 `docs/stories/{姓名}-v3.md`。**核心：用 `ts-meta` + `ts-dialog` 代码块承载机器可解析数据，其余 markdown 给人读**。转换器只认这两种代码块，写错格式会被拒收。

### 文档结构

| 章节 | 内容 | 机器读？ |
|---|---|---|
| 标题行 | `# {姓名} · v3 · {档位}剧本 · {节拍}节拍` | 否 |
| 〇 人物档案 | intro / surface / truth 的叙事说明 | 否 |
| 一 剧本元信息 | 一个 ```ts-meta 代码块 | **是** |
| 二 记忆碎片 | 放 ts-meta 的 `memoryFragments` 字段 | **是** |
| 三 节拍骨架 | 每节拍：节拍说明（人读）+ 该节拍全部 ```ts-dialog 节点块（机器读） | **是** |
| 四 结局 | 结局节点是 dialogues 里的 `isEnding` 节点 | **是** |
| 六 状态 | 验收勾选 | 否 |

### ts-meta 代码块（场景元信息）

首行必须是注释 `// id: <场景id>`（决定生成文件名与聚合 import），随后若干 `// key: value` 验证参数注释（`--walk` 生成测试时读取），然后是一个完整的 `PatientScenario` 对象字面量——**不含 `dialogues` 字段**（由全部 ts-dialog 块汇总填充）：

````markdown
```ts-meta
// id: lin_xiao
// tier: 长
// anchor: 15,30,50,65,75,80,88
// truthEnd: 100
// minCureRounds: 100
// fragments: 3
// worsenAtMost: 70
{
  id: "lin_xiao",
  name: "林晓",
  title: "高二女生 · 被班主任转介",
  intro: "…",
  surface: "…",
  truth: "…",
  palette: { primary: "#…", secondary: "#…", fog: "#…", bright: "#…" },
  baseReward: 800,
  difficulty: "困难",
  startNode: "l1_start",
  initialState: { trust: 15, defense: 70, mood: 35, truth: 0, round: 0 },
  memoryFragments: [
    { id: "lin_m1", trigger: { truth: 30 }, title: "…", text: "…", emotion: "sad" },
  ],
}
```
````

验证参数注释（`--walk` 生成测试时读取并断言）：

- `tier` — 短 / 中 / 长
- `anchor` — 每节拍末 trust 期望，逗号分隔（如 `15,30,50,65,75,80,88`）
- `truthEnd` — truth 终点期望
- `minCureRounds` — cure 主线最少轮数
- `fragments` — 均衡玩家应触发碎片数下限
- `worsenAtMost` — 恶化入口 trust 上限

### ts-dialog 代码块（对话节点）

每个对话节点一个代码块，首行 `// id: <节点id>`，内容为单个 `DialogueNode` 对象字面量：

````markdown
```ts-dialog
// id: l1_c01
{
  id: "l1_c01",
  speaker: "doctor",
  text: "〔节拍1 · 初访〕你班主任说，你最近状态不太对。",
  choices: [
    { id: "l1_c01_a", text: "「听起来，你这阵子过得很辛苦。」", kind: "empathy", effect: { trust: 2, defense: -2 }, next: "l1_p2" },
    { id: "l1_c01_b", text: "「月考第七名，怎么反而来找我？」", kind: "probe", effect: { trust: 1, truth: 2 }, next: "l1_p2" },
    { id: "l1_c01_c", text: "「第七名不错了，别给自己太大压力。」", kind: "logic", effect: { trust: -8, defense: 6 }, next: "l1_r1" },
  ],
}
```
````

### 硬性格式规则（违反转换器会带行号拒收）

1. 代码块围栏语言标签**精确**为 `ts-meta` / `ts-dialog`；其它块（json / ts 等）不参与解析。
2. 每个代码块首行是 `// id: <id>` 注释，且与块内对象的 `id:` 字段一致。
3. 对象字面量里的枚举值（`speaker` / `kind` / `emotion` / `difficulty` / `endingType`…）必须是 `lib/types.ts` 里的合法值——生成后由 `tsc --noEmit` 兜底报错。
4. `text` 用单引号 / 双引号 / 反引号；中文引号「」无需转义；多行文本用反引号模板串。
5. doctor 节点必须含 `choices`（≥ 2 条），每条 choice 必须带 `next` 且指向存在的节点 id。
6. 结局节点（`isEnding: true`）必须含 `endingType` / `endingTitle` / `endingText` / `endingReward`。
7. 患者口述（`speaker: "patient"`）文本零叙事性时间词（第二天 / 一个月后 / 后来有一天…）。
8. 所有 `next` / `autoNext` 引用的节点必须存在（无悬空）。
9. 不要在 ts-meta 里写 `dialogues`——整个 dialogues 由全部 ts-dialog 块自动汇总。
10. 节拍结束节点（`speaker: "narration"` + 患者离开文案）必须含 `beatEnd: { resumeNode }`，且边界数 = 档位节拍数 − 1（短 3 / 中 4 / 长 5），`resumeNode` 指向下一节拍起始节点（如 `l1_out` → `l2_start`）；末节拍（`isEnding` 结局节点）**不加 beatEnd**。缺标记 / 边界数不符 / resumeNode 悬空都会被转换器带行号拒收。
