## 背景

诊所大厅是游戏的主界面（`components/game/ClinicHall.tsx`），承担「浏览预约 → 接诊 → 成长经营」的全部主循环入口。外部智能体对首页提出了约 20 条优化建议。本设计文档记录**逐条评估结论**与**本轮落地清单**，明确「做 / 不做 / 延后」及理由，防止无边界改动破坏已稳定的信息架构。

## 评估结论

### 拒绝（明确理由）

| 建议 | 拒绝理由 |
|------|---------|
| 排序切换（按难度/紧急） | 当前预约池 ≤ 5 人，排序价值极低；引入状态与切换 UI 属于 YAGNI |
| 右侧次要模块折叠为下拉 | 6 个按钮信息密度适中，折叠反而降低可达性、多一次点击 |
| 卡片点击弹「接待确认框」 | 卡片整体即点击区域，再加确认框徒增摩擦，破坏操作效率 |
| 移动端响应式重排 | 发布场景为桌面端（小红书/B站引流到 Web），移动端归入 v1.1+ P2 |

### 延后（P1 顺带）

- HUD 顶部图标风格统一

## 交互决策记录

1. **卡片 hover 展开摘要**而非「点击展开」：卡片点击语义是「接诊」，任何额外的展开交互都会与主操作冲突。hover 展开零摩擦、不改变点击语义。
2. **退出确认文案采用「进度会自动保存」**：游戏已有 800ms 防抖自动存档，若写「未保存进度将丢失」属于误导；确认框作用是防误触而非风险警示。
3. **难度图标不新增 DOM 节点**：直接拼进现有 `patient-difficulty` 标签文本，避免影响现有布局与测试。

## 验证方式

- `npm run typecheck` + `npm test`（引擎 18 项单测）
- Playwright 实测：新游戏 → 大厅 → 校验进度条/天数徽章/新增预约/退出确认/理智低高亮
- 引导全流程重验：`[data-guide]` 定位替代 nth-child 后 3 步高亮正确
