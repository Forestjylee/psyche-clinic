# 派活提示词 · 新剧本产出 → v3 可执行剧本

> 使用方式：把「## 任务内容」开始的整段复制给目标 agent。
> 派活时需填两个占位：`<主题>`（一句话，如「急诊科护士，长期面对生离死别后开始逃避值班」）、`<档位>`（短 / 中 / 长，可留空让 agent 按主题复杂度自定）。

---

## 任务内容

你是「心灵诊所」游戏项目的剧本创作工程师。你的任务：从给定的主题出发，从零创作一个完整患者剧本，输出为 **v3 机器可解析剧本**（ts-meta + ts-dialog 代码块），运行转换器生成可执行的 `patient.ts`，并通过走线验收测试。

**输入**：主题 `<主题>`，档位 `<档位>`（短 / 中 / 长）
**输出**：`docs/stories/<患者id>-v3.md` + `lib/data/patients/<患者id>.ts` + `lib/data/<患者id>.walk.test.ts`（聚合入口 glob 自动收集，无需手动接）

---

### 第 0 步 · 必读资料（按序读，别跳过）

1. `docs/stories/剧本编写提示词.md` —— **v3 输出格式规范**（ts-meta / ts-dialog 硬性规则、三档数值曲线）。这是你写代码块的依据。
2. `docs/stories/chen-mo-v3.md` —— 短档 v3 剧本活样板（节拍组织、碎片、恶化入口、分叉结局怎么落）。
3. `docs/stories/lin-xiao-v3.md` —— 人物档案标准范本（看它怎么设计一句话核心、三层真相、角色三角、症状意义、关键转折）。
4. `docs/stories/剧本登记表.md` —— 全部剧本的内容概述索引，**创作前必读，防雷同**。
5. `lib/data/patients/lin_xiao.ts` —— 已存在的长档手写版（参考长档节点密度；**不要改动**）。
6. `scripts/md-to-patient.mjs` —— 转换器（输入校验规则）。
7. `lib/engine/walk.ts` —— 走线器 + PICKS 四策略（走线判定逻辑）。

### 第 1 步 · 人物设计（动笔前先想清楚）

**先查重**：读 `docs/stories/剧本登记表.md`，确认你的核心困境/主题/身份设定不与表中任一已有剧本雷同（同一困境换皮=违规）。登记表末尾的「防雷同提示」列了已被占位的坑位，新剧本避开。不雷同再往下写。

仿照 lin-xiao-v2 / chen-mo-v3 的人物档案，写出：

- **姓名/年龄/职业/来诊渠道**（谁送来的、为什么是现在）
- **一句话核心**：这个人的困境用一个比喻说透
- **三层真相**：表层（开场就说，症状）+ 中间层（第 2-3 节拍揭，具体事件）+ 深层（核心信念，根源，儿童期成因）
- **角色三角**：施压者（谁在施加压力）/ 情感忽视者（谁没接住）/ 被守护者（他在保护谁）——至少两角具象
- **症状意义**：症状不是病，是他在某个处境下的「求生方式」，开场埋、中段被问、高潮意义反转
- **关键转折**：整场最重要的一个瞬间（一句话或一个动作），是情感顶点

人物设计要符合游戏定位：**弱化治疗术语，强调人与人的连接**。不出现 CBT / 催眠 / 药理等术语（见剧本编写提示词.md 的用词要求）。

### 第 2 步 · 定档位 + 节拍规划

档位决定规模，按三档标准选（派活已指定就用指定档）：

| 档 | 节拍 | 轮数 | trust 锚点 | truth 终点 | 碎片阈值 | 恶化入口 | 隐藏结局门槛 |
|---|---|---|---|---|---|---|---|
| 短 | 4 | 40+ | 15→28→40→50→58 | 40 | 30 | ≤40 | 50 |
| 中 | 5 | 70+ | 15→30→45→57→65→70 | 70 | 25 / 50 | ≤55 | 65 |
| 长 | 6 | 100+ | 15→30→50→65→75→80→88 | 100 | 30 / 40 / 80 | ≤70 | 80 |

每节拍规划：主题一句话、trust 起止、truth 起止、1 个阻抗节点、1 个关键事件、碎片落点、过场（narration）归位。把节拍规划表写在剧本开头（给审稿人看，也给自己定数值）。

**数值口径**：

- trust 单调递增（信任合并线），empathy 与 probe 同涨 trust；轻推进 +1~+2、实质 +2~+3、纯过场 +0；logic/prescribe 失误显著负值 -5~-15
- truth 只由 probe 涨（轻 +2、实质 +3），碎片阈值随节拍递进
- defense 净下降，阻抗节点短时 +8~+12 再回落
- 每节拍约 1/3 实质选择（带 require 或较大 effect），2/3 轻推进（在场感细节）

### 第 3 步 · 写 ts-meta 代码块

首行 `// id: <患者id>` + 验证参数注释 + `PatientScenario` 对象字面量（不含 dialogues）。

- **患者 id**：中文名转拼音 snake_case，且**必须全局唯一**（现有：`lin_xiao` / `chen_mo` / `xiao_bei`）。id 一旦定下，生成的文件名、节点前缀都跟着它。
- **验证参数**：

  ```text
  // tier: <短/中/长>
  // anchor: <节拍末 trust，逗号分隔>
  // truthEnd: <truth 终点>
  // minCureRounds: <该档 cure 主线最少轮数>
  // fragments: <碎片数>
  // worsenAtMost: <恶化入口 trust 上限>
  ```

- **memoryFragments**：碎片 trigger 落在节拍规划的 truth 阈值点，内容是与深层信念呼应的闪回场景。
- palette 色调、baseReward（短 650 / 中 750 / 长 850 参考）、difficulty 与档位匹配。

### 第 4 步 · 写 ts-dialog 代码块（核心工作量）

按 v3 规范逐节点写，每节拍铺满：

- 节拍首 = 患者入场/事件节点，节拍末 = 过场（narration）归位 + 数值回中
- 每节拍 1 个阻抗节点（逻辑说教选项，defense 短时回升，走失误线）
- 每节拍 1 个关键事件节点（实质选择，带 require 门槛，推动真相）
- doctor 节点 choices ≥ 2，每条带 next；关键分叉可 3 条（empathy 主线 / probe 真相线 / logic 失误线）
- 结局节点：`cure`（治愈，主线必经）+ `acceptance`（接纳，玩家没彻底揭开但患者和解）+ `worsen`（恶化，失误线）+ 长/中档加 `hidden`（伦理强制介入，高 trust 门槛）
- **完整走通**：startNode → 各节拍 → 结局，引用无悬空

**文风要求**（仿 lin-xiao / chen-mo）：

- 患者口述口语化，带小动作/停顿（「……」「（她低头）」），不书面
- 医生的 choice 文本是「人话」，不是咨询术语；empathy 接住情绪、probe 温和推进、logic 是「过来人式说教」（带负面效果）
- 零叙事时间词（第二天/一个月后/后来有一天/次日…）；时间跳跃一律用 narration 过场节点表达
- 多行文本用反引号模板串；中文引号「」直接写，无需转义

### 第 5 步 · 转换器生成 + 结构校验

```bash
node scripts/md-to-patient.mjs docs/stories/<患者id>-v3.md --walk
```

成功输出 `✓ 生成 <患者id>.ts` + `✓ 生成 <患者id>.walk.test.ts` + `tsc --noEmit 通过`。被拒收就按报错行号修剧本重跑。

### 第 6 步 · 走线测试必须四线全绿

```bash
npx vitest run lib/data/<患者id>.walk.test.ts
```

四线断言（来自 ts-meta 注释）必须全过：

- **共情线** → cure，trust 达锚点末位，轮数 ≥ minCureRounds
- **均衡线** → cure，碎片触发 ≥ fragments
- **失误线** → worsen，trust ≤ worsenAtMost
- **探问线** → cure，truth 冲顶 ≥ truthEnd

不达标就微调 choice `effect`，重跑转换器 + 走线，直到全绿。**走线全绿是硬验收。**

### 第 7 步 · 接入聚合入口

`lib/data/patients.ts` 的患者池由 `scripts/scan-patients.mjs` 扫描 `lib/data/patients/` 目录自动生成聚合索引（`index.generated.ts`），**新剧本放进去即自动进池，无需改聚合入口**（`npm run dev`/`npm test`/`npm run build` 的 pre 钩子会自动重新生成索引；不用 `import.meta.glob`，那是 Vite 特性，Next.js/webpack 浏览器端不兼容）。跑走线测试后执行：

```bash
npm test
```
